# Database schema

The active schema is defined in [sqlite.js](../backend/src/infrastructure/database/sqlite.js). Operational domains include organizations, users and auth sessions; studios/stations and pairing; station graphics, automations, playout and as-run records; audit logs. FFT/media binaries and videos stay outside the database. The new Agent connection heartbeat and telemetry freshness are in memory and reset at reconnect. See [deployment](DEPLOYMENT.md) for data backup requirements.

`station_agent_credentials` stores only the current positive generation per station. Absence denotes legacy generation zero. The row is removed with the station. Generation changes, pairing-code invalidation and the audit event commit in one transaction. Agent tokens and OBS passwords are excluded from these audit events.

## Phase Three media library schema

Phase Three adds four relational tables in [sqlite.js](../backend/src/infrastructure/database/sqlite.js) and matching MySQL models in [schema.prisma](../backend/database/prisma/schema.prisma) behind `IMediaRepository` ([sqlite-media-repository.js](../backend/src/infrastructure/repositories/sqlite-media-repository.js)):

- `media_assets` (`MediaAsset`): stores organization-scoped media metadata (`id`, `organizationId`, `folder`, `title`, `description`, `category`, `kind`, `tags`, `channelIds`, `originalFilename`, `storageKey`, `thumbnailKey`, `previewKey`, `sizeBytes`, `checksumSha256`, `mimeType`, `containerFormat`, `videoCodec`, `audioCodec`, `width`, `height`, `frameRate`, `durationSeconds`, `bitrateBps`, `audioChannels`, `sampleRateHz`, `hasVideo`, `hasAudio`, `uploadStatus`, `processingStatus`, `broadcastCompatibility`, `compatibilityNotes`, `errorReason`, `createdByUserId`, `createdAt`, `updatedAt`). No media bytes are stored as database BLOBs.
- `media_upload_sessions` (`MediaUploadSession`): tracks resumable chunked uploads, quota reservations (`expectedSizeBytes`), verified byte progress (`receivedBytes`), `.part` staging keys (`uploadKey`), expiration (`expiresAt`) and final linked `assetId`.
- `media_processing_jobs` (`MediaProcessingJob`): durable asynchronous FFprobe/FFmpeg inspection jobs linked to `media_assets` with cascade deletion.
- `media_playlists` (`MediaPlaylist`): organization-scoped `VIDEO` and `AUDIO` playlists referencing validated `READY` media assets for movie-channel and independent-audio scheduling.

Legacy short-clip tables (`ad_assets`, `ad_frames`, `ad_asset_audio`) remain in SQLite for backward compatibility with existing Phase 1–2 native scene and advertising receiver fixtures until Phase 15 migrates runtime persistence to MySQL.

## Phase 15 MySQL persistence foundation and Phase Four video sources schema

- `video_sources` (`VideoSource` in [schema.prisma](../backend/database/prisma/schema.prisma) and [sqlite.js](../backend/src/infrastructure/database/sqlite.js)): stores organization-scoped unified video sources across all 10 source types (`UPLOADED_FILE`, `MOVIE`, `PLAYLIST`, `OBS_LIVE`, `HLS_STREAM`, `RTMP_STREAM`, `SRT_STREAM`, `RTSP_STREAM`, `REMOTE_VIDEO_URL`, `SERVER_FILE`), encrypted stream credentials (`encryptedSecret` via AES-256-GCM, never returned in API payloads), probed stream parameters (`width`, `height`, `frameRate`, `videoCodec`, `audioCodec`, `hasAudio`, `previewThumbnailKey`), connection and availability states (`ONLINE`, `OFFLINE`, `CONNECTING`, `RECONNECTING`, `DEGRADED`, `ERROR` / `AVAILABLE`, `UNAVAILABLE`, `PROBING`, `FALLBACK_ACTIVE`), bounded reconnection settings (`reconnectEnabled`, `maxRetries`, `retryCount`, `backoffBaseMs`, `backoffMaxMs`), and fallback policy (`fallbackMode`, `fallbackSourceId`, `fallbackAssetId`).
- [prisma-repositories.js](../backend/src/infrastructure/repositories/prisma-repositories.js) and [prisma-station-repository.js](../backend/src/infrastructure/repositories/prisma-station-repository.js) implement the MySQL Prisma adapters for `IUserRepository`, `IStationRepository`, `IAuditLogRepository`, `IMediaRepository`, `IVideoSourceRepository`, and pairing tokens, selectable via `RepositoryFactory` ([repository-factory.js](../backend/src/infrastructure/repositories/repository-factory.js)).
- [sqlite-to-mysql-migration.js](../backend/scripts/sqlite-to-mysql-migration.js) performs non-destructive forward migration from an existing SQLite database (opened read-only) into MySQL transactions and verifies row-count parity across all migrated entities.

## Phase Five independent audio sources and mixer schema

- `audio_sources` (`AudioSource` in [schema.prisma](../backend/database/prisma/schema.prisma) and [sqlite.js](../backend/src/infrastructure/database/sqlite.js)): stores organization- and channel-scoped independent audio sources across all 11 source types (`UPLOADED_AUDIO`, `MUSIC_PLAYLIST`, `INTERNET_RADIO`, `ICECAST_STREAM`, `SHOUTCAST_STREAM`, `MICROPHONE_INPUT`, `VIDEO_EXTRACTED_AUDIO`, `OBS_AUDIO_INPUT`, `ADVERTISEMENT_AUDIO`, `FALLBACK_AUDIO`, `GENERATED_SILENCE`), AES-256-GCM encrypted stream secrets (`encryptedSecret`), per-source mixing controls (`enabled`, `muted`, `soloMonitoring`, `volumeLinear`, `gainDb`, `delayMs`, `fadeInMs`, `fadeOutMs`, `priority`, `duckingTrigger`, `duckingTarget`), playlist and crossfade parameters (`repeatMode`, `shuffleEnabled`, `crossfadeMs`, `currentTrackIndex`, `currentTrackAssetId`), runtime levels (`state`, `measuredRmsDbfs`, `measuredPeakDbfs`, `clippingDetected`, `codec`, `sampleRateHz`, `channels`, `streamMetadata`), and bounded reconnection/fallback policies (`reconnectEnabled`, `maxRetries`, `retryCount`, `backoffBaseMs`, `backoffMaxMs`, `fallbackSourceId`, `fallbackAssetId`).
- `audio_mixer_configs` (`AudioMixerConfig` in [schema.prisma](../backend/database/prisma/schema.prisma) and [sqlite.js](../backend/src/infrastructure/database/sqlite.js)): composite primary key `(channelId, organizationId)` storing master volume/gain/mute, routing mode (`AUDIO_ROUTING_MODES`), `cameraAudioMuted`, `cameraAudioGainDb`, priority ducking envelope parameters (`duckingEnabled`, `duckingThresholdDbfs`, `duckingReductionDb`, `duckingAttackMs`, `duckingHoldMs`, `duckingReleaseMs`), `crossfadeDurationMs`, `adAudioPolicy`, `adActive`, `peakLimiterCeilingDbfs`, `silenceThresholdDbfs`, `silenceTimeoutSeconds`, fallback references, and measured master RMS/Peak dBFS meters.
- Version-controlled SQL migration: [20261128_0001_phase15_and_phase05_foundation/migration.sql](../backend/database/prisma/migrations/20261128_0001_phase15_and_phase05_foundation/migration.sql) and [migration_lock.toml](../backend/database/prisma/migrations/migration_lock.toml).

## Phase Six multi-channel server-side playout schema
