# Linux deployment proposal

Provision an isolated Ubuntu Server LTS staging VM to qualify the selected OS, Docker Engine and Compose versions, Nginx, MySQL/InnoDB, supported Node.js LTS and Vite production assets. Pin images and media runtimes by digest after validating compatibility. Exercise Python/PyGObject, GStreamer and FFmpeg decode, encode and mux elements in the exact worker image. Qualify GPU drivers and software fallback separately. The current Compose definition uses SQLite. This proposal does not deploy or change it to MySQL.

- Network. Publish TLS through Nginx for the management domain. Preserve exact origins, secure cookies, WSS, CSP and reviewed forwarded-IP trust. Apply rate limits and sanitized logs. Reach SSH through an owner-approved management network with key authentication. Keep MySQL, worker RPC and ingest private. Place provider delivery and high-volume ingest in separate traffic and credential scopes.
- Services. Use non-root dedicated API, worker and backup identities, least-privilege mounts, bounded temporary storage, read-only root where compatible and independent restart policies. Browser and workstation outages do not stop workers. Check actual decoded receiver health in addition to process liveness.
- Persistence. Mount dedicated media, MySQL and backup storage independently of images. Begin media sizing at 500 GB–1 TB and measure ingest, derivatives, multiple schedules, retention and restore capacity. At the proposed 4–6 Mbps per channel, two video outputs together consume 8–12 Mbps before audio, protocol overhead and per-provider copies. Provision from measured peak rather than this estimate. Keep protected off-host encrypted backups of data, manifests and key references with rehearsed restoration.
- Staging prerequisites. Provide a disposable Linux VM with Docker access, MySQL, temporary TLS, an independent receiver, isolated OBS/Windows staging, permitted camera and movie fixtures, and a provider simulator. Size CPU, RAM, GPU and storage from benchmark evidence. Obtain owner approval for DNS, external provider access, maintenance, credentials or production deployment.

Use [update and rollback procedures](UPDATE_AND_ROLLBACK_PLAN.md) and [receiver acceptance](BROADCAST_ACCEPTANCE_PLAN.md) before any production change.
