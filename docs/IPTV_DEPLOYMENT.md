# نشر IPTV المحمي على Linux

تستخدم تهيئة Compose الاختيارية عامل الوسائط داخل الخادم. يخزّن العامل مؤقتًا قوائم HLS والمقاطع داخل حاوية الخادم، ويخدمها التطبيق عبر HTTPS مع صلاحيات المحطة. الطلبات إلى المسار الثابت القديم `/iptv/` ترجع 404. راجع [خطة Linux](DEPLOYMENT_PLAN.md) للنشر الإنتاجي المقترح.

1. جهّز جهاز اختبار Linux معزولًا وDocker وCompose وشهادة اختبار صالحة للدومين المرحلي. استخدم ملف بيئة خاصًا وإعدادات SQLite الاصطناعية في هذه المرحلة.
2. شغّل ملف Compose الأساسي مع `docker-compose.iptv.yml` بعد التحقق من الإعداد. استخدم اسم مشروع منفصلًا عن أي تثبيت عامل، واضبط معرف محطة اختباريًا. استخدم مادة اصطناعية أو إدخال loopback. يتطلب HTTPS الوارد وكيل الخروج المحلي المعتمد.
3. افتح لوحة المحطة، وابدأ **Program**، وانتظر جاهزية HLS. أنشئ رابط IPTV من اللوحة أو استخدم مشغّلًا يرسل مصادقة التطبيق. تعامل مع الرابط الموقّع باعتباره بيانات اعتماد مؤقتة.
4. تحقّق بواسطة مستقبل مستقل من الصوت والصورة، ومن رفض القائمة والمقاطع بدون صلاحية، ومن منع المحطات الأخرى وإبطال الرابط بانتهاء الجلسة. تحقّق أيضًا من أن مسارات القائمة والمقاطع القديمة ترجع 404 عبر Nginx. سجّل زمن الانقطاع عند تبديل المصدر.
5. احتفظ ببيانات المحطات والتخزين عند التراجع، وأبقِ المسار الثابت مغلقًا. لا تستعد تكوينًا يعيد نشر الوسائط خارج المصادقة.

مسار المزوّد الدائم بصلاحيات منفصلة لكل قناة ضمن خارطة الطريق. تحقق Compose وNginx الفعلي مطلوب في بيئة Linux مصرح بها.
