# API documentation

The existing [API reference](API_SPECIFICATION.md) and [backend reference](../backend/docs/API_DOCUMENTATION.md) describe request details. The Phase Zero route-family inventory below reflects the current working tree. Implementations and route middleware govern actual behavior.

`GET /api/v1/stations` accepts optional `status` (`ONLINE`, `OFFLINE`, `DEGRADED`, `CONNECTING`) and `streamStatus` (`STOPPED`, `STARTING`, `STREAMING`, `STOPPING`) filters. Supply each filter at most once. Empty, unknown or repeated values return HTTP 400. The station list is scoped to the authenticated organization.

On station creation or reassignment, a non-null `studioId` must identify a studio in the station's organization. A missing or out-of-organization studio returns HTTP 404. `PATCH` with `studioId: null` clears the assignment.

Station creation and updates accept only `name`, `studioId`, `description`, `ipAddress`, `obsPort` and `obsPassword`. Extra fields return HTTP 400. Organization and runtime state are server-managed.

`POST /api/v1/stations/:id/audio/volume`, `POST /api/v1/stations/:id/audio/mute`, and `POST /api/v1/stations/:id/studio-mode/transition` verify station ownership within the caller's organization before dispatching to the connected Agent, enforce strict payload schemas (requiring at least one volume parameter on volume updates and rejecting undeclared fields with HTTP 400), and record organization-scoped `AUDIO_VOLUME_UPDATED`, `AUDIO_MUTE_UPDATED`, and `TriggerStudioModeTransition` audit events.

Legacy graphics writes (`/api/v1/stations/:id/graphics/*`), playout schedule and control writes (`/api/v1/stations/:id/playout*`), native Program scene and schedule mutations (`/api/v1/stations/:id/program/local-scene*`), and signed IPTV playback-link issuance (`POST /api/v1/stations/:id/program/hls/playback-link`) enforce strict request schemas and record organization-scoped audit events.

Login and Agent pairing claims have independent per-IP limits of 10 requests per 15 minutes. Each endpoint returns HTTP 429 with `Retry-After` when its limit is reached. The global API limit also applies.

`GET /api/v1/logs` requires `audit:read` and returns only the authenticated user's organization events, newest first. The optional `limit` query parameter accepts one integer from 1 to 500 and defaults to 100. Invalid and repeated values return HTTP 400.

`POST /api/v1/users` requires `user:manage`, enforces `accountChangeLimiter`, and accepts only `fullName`, `email`, `password`, `role` and `currentPassword` (the administrator's current password for reauthentication). Extra properties return HTTP 400 and an invalid administrator password returns HTTP 403. An HTTP 201 response confirms the account and its organization-scoped `USER_CREATED` audit event were saved together. Responses from the users and audit routes carry `Cache-Control: no-store`.

`/api/v1/media/*` sets `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer`. `GET /api/v1/media/storage`, `GET /api/v1/media/assets`, `GET /api/v1/media/assets/:id`, `GET /api/v1/media/assets/:id/thumbnail`, `GET /api/v1/media/assets/:id/preview` (supporting `Range: bytes=...` with HTTP 206), `GET /api/v1/media/uploads*` and `GET /api/v1/media/playlists` require `station:read`. `POST /api/v1/media/uploads`, `PATCH /api/v1/media/uploads/:id` (`Content-Type: application/offset+octet-stream` and `Upload-Offset`), `POST /api/v1/media/uploads/:id/complete`, `DELETE /api/v1/media/uploads/:id`, `GET/POST /api/v1/media/import/directory`, `POST /api/v1/media/import/url`, `PATCH /api/v1/media/assets/:id` and `POST /api/v1/media/playlists` require `media:upload`. `DELETE /api/v1/media/assets/:id?confirm=true`, `DELETE /api/v1/media/playlists/:id` and `POST /api/v1/media/storage/cleanup` require `media:delete`. See [MEDIA_LIBRARY_ARCHITECTURE.md](MEDIA_LIBRARY_ARCHITECTURE.md).

`/api/v1/video-sources/*` sets `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer`. `GET /api/v1/video-sources`, `GET /api/v1/video-sources/:id` and `GET /api/v1/video-sources/:id/preview` require `station:read`. `POST /api/v1/video-sources`, `PATCH /api/v1/video-sources/:id`, `POST /api/v1/video-sources/:id/probe` and `DELETE /api/v1/video-sources/:id?confirm=true` require `video:manage` and record organization-scoped `VIDEO_SOURCE_CREATED`, `VIDEO_SOURCE_UPDATED`, `VIDEO_SOURCE_PROBED` and `VIDEO_SOURCE_DELETED` audit events.

`/api/v1/channels/:channelId/audio*` sets `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer` and verifies that `:channelId` belongs to the caller's organization (returning HTTP 404 otherwise). `GET /api/v1/channels/:channelId/audio` and `GET /api/v1/channels/:channelId/audio/sources` require `station:read`. `PATCH /api/v1/channels/:channelId/audio/mixer`, `POST /api/v1/channels/:channelId/audio/sources`, `PATCH /api/v1/channels/:channelId/audio/sources/:id`, `POST /api/v1/channels/:channelId/audio/sources/:id/probe`, `POST /api/v1/channels/:channelId/audio/sources/:id/microphone`, `POST /api/v1/channels/:channelId/audio/sources/:id/microphone/pcm`, `POST /api/v1/channels/:channelId/audio/step`, and `DELETE /api/v1/channels/:channelId/audio/sources/:id?confirm=true` require `audio:manage` and record organization-scoped `AUDIO_SOURCE_CREATED`, `AUDIO_SOURCE_UPDATED`, `AUDIO_SOURCE_PROBED`, `AUDIO_SOURCE_DELETED`, `AUDIO_MIXER_CONFIG_UPDATED`, `MICROPHONE_ACTIVATED`, and `MICROPHONE_DEACTIVATED` audit events. See [AUDIO_ARCHITECTURE.md](AUDIO_ARCHITECTURE.md).

`/api/v1/channels/:channelId/playout*` sets `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer` and verifies organization ownership of `:channelId`. `GET /playout` and `GET /playout/monitor-frame` require `station:read`. `PATCH /playout/config` requires `station:manage` and supports optimistic revision concurrency (`expectedRevision`). `POST /playout/lifecycle` (`start`, `stop`, `restart`), `POST /playout/camera/switch`, `POST /playout/camera/exclude`, `POST /playout/movie/select`, `POST /playout/movie/seek`, and `POST /playout/movie/pause` require `station:control`. `POST /playout/emergency` requires `broadcast:emergency` and records `CHANNEL_EMERGENCY_ACTIVATED` / `CHANNEL_EMERGENCY_CLEARED` audit events. See [PLAYOUT_ENGINE_ARCHITECTURE.md](PLAYOUT_ENGINE_ARCHITECTURE.md).
